# 악보 변환 (PDF·사진 → 피아노 MusicXML)

중학교 1학년 학생이 안드로이드 태블릿 앱(`app/`)으로 연습할 악보를 만든다.
결과물은 `app/scores/` 의 `.musicxml` 파일과 갱신된 `app/scores/index.json` 이다.

## 0. 입력 확인
- 입력: 사용자가 준 경로, 없으면 `scores/inbox/` 의 PDF·이미지 파일.
- 요청에서 다음을 파악한다. 말하지 않았으면 **기본값으로 진행**하고 결과 보고 때 알린다(질문으로 멈추지 않는다).
  - 난이도: 기본 `원곡` + `쉬움` 두 버전
  - 조옮김: 기본 없음
  - 템포: 악보 표기값, 없으면 곡 성격에 맞게(대개 80~110)
  - 손가락 번호: 쉬움 버전에는 주요 위치(각 프레이즈 시작, 손 위치 이동)에 넣는다

## 1. 악보 읽기
- PDF는 페이지를 이미지로 보고(Read 도구는 PDF `pages` 지원), 사진은 그대로 Read 한다.
  흐리거나 작으면 페이지/영역별로 나눠 다시 읽는다.
- 먼저 **전체 구조**를 메모한다: 제목, 작곡가, 조표, 박자표, 템포, 마디 수, 반복기호(도돌이표·D.C.·1/2번 괄호), 셈여림.
- 그다음 **마디 단위로** 오른손/왼손을 옮긴다. 각 마디마다 박자 합이 박자표와 맞는지 스스로 센다.
- 확신이 없는 마디는 번호를 기록해 두고 보고 때 "확인 필요"로 알린다. 지어내지 않는다.
- 피아노 악보가 아닌 경우(멜로디 악보, 코드 악보, 다른 악기):
  - 멜로디 → 오른손, 코드 기호 → 왼손 반주를 직접 편곡한다(아래 난이도 규칙 적용).
  - 가사는 넣지 않는다(앱에서 쓰지 않음).

## 2. MusicXML 작성 규칙 (앱 호환 필수)
- `score-partwise` version 3.1, 파트 1개(`P1`, Piano), `<staves>2</staves>`, staff 1 = 높은음자리표, staff 2 = 낮은음자리표.
- 오른손 voice 1(필요시 2), 왼손 voice 5(필요시 6). 손을 바꿀 때 `<backup>` 으로 마디 처음으로 돌아간다.
- 모든 `<note>` 에 `<duration>`, `<voice>`, `<type>`, `<staff>` 를 넣는다. 화음은 `<chord/>`.
- `<divisions>` 는 필요한 최소 단위로(8분음표까지 → 2, 16분 → 4, 셋잇단 → 3의 배수).
- 첫 마디에 `<direction><sound tempo="..."/></direction>` 와 metronome 표기를 넣는다.
- 못갖춘마디(pickup)는 `<measure number="0" implicit="yes">`.
- 붙임줄은 `<tie type="start|stop"/>` + `<notations><tied .../></notations>`. 앱은 tie stop 음을 다시 치지 않는 것으로 판정한다.
- **반복은 펼쳐서 쓴다**: 앱 커서는 도돌이표를 따라가지 않으므로 도돌이표·D.C.·1/2번 괄호는 실제 연주 순서대로 마디를 풀어 쓴다.
- 꾸밈음(grace)은 쉬움/보통 버전에서는 빼고, 원곡에서만 `<grace/>` 로 둔다(앱은 판정하지 않음).
- 손가락 번호: `<notations><technical><fingering>1</fingering></technical></notations>`.
- 제목 `<work-title>` 끝에 난이도를 붙인다: `곡명 (쉬움)`.
- 예시 형식은 `app/scores/twinkle_easy.musicxml` 을 참고한다.

## 3. 난이도 규칙
| 항목 | 쉬움 | 보통 | 원곡 |
|---|---|---|---|
| 오른손 | 멜로디만(위 성부), 화음 제거 | 멜로디 + 강박에서만 2음 화음 | 그대로 |
| 왼손 | 마디당 근음 1~2개(온/2분음표) | 근음+5도, 또는 단순한 분산화음(도-솔-미-솔) | 그대로 |
| 리듬 | 16분 → 8분, 셋잇단·당김음 단순화, 쉼표가 짧으면 앞 음을 늘림 | 16분은 유지하되 복잡한 당김음 단순화 | 그대로 |
| 음역 | 손 위치 이동 최소화(가능하면 오른손 C4~G5, 왼손 C3~G3) | 옥타브 이동 줄이기 | 그대로 |
| 조 | 샵/플랫 3개 이상이면 C·G·F·D 장조(또는 a·e·d 단조)로 조옮김 제안·적용 | 4개 이상이면 조옮김 고려 | 그대로 |
| 템포 | 원 템포의 80% 정도 | 90% | 100% |
| 장식 | 꾸밈음·트릴·아르페지오 제거 | 트릴 → 2음 반복으로 단순화 | 그대로 |

편곡은 음악적으로 자연스러워야 한다: 화성 진행을 지키고, 멜로디 윤곽은 바꾸지 않는다.

## 4. 파일 이름
`app/scores/<영문_소문자_곡명>_<easy|normal|original>.musicxml`
예: `canon_d_easy.musicxml`, `canon_d_original.musicxml`

## 5. 검증 (반드시 실행, 오류 0개가 될 때까지 수정)
```bash
node tools/score-tool.mjs validate app/scores/<파일들>
node tools/score-tool.mjs index      # 앱 곡 목록 갱신
```
- 박자 초과/부족, XML 구조, 음역, 성부 길이를 검사한다.
- 검증 통과 후에도 원본과 마디 수·조표·박자표가 맞는지 다시 대조한다.

## 5-1. 들려주기 (항상 실행)
```bash
node tools/score-tool.mjs midi app/scores/<파일들>            # → scores/listen/*.mid
node tools/score-tool.mjs midi app/scores/<파일> --tempo 80   # 느린 버전
```
- `.mid` 는 PC에서 더블클릭하면 피아노 소리로 재생된다. 보고 때 전체 경로를 알려준다.
- 사용자가 "들어보고 고르고 싶다", "바꿔서 들려줘"라고 하면 **버전 A/B(…)** 를 만든다.
  예: `곡_easy_a`(왼손 근음만), `곡_easy_b`(왼손 분산화음), 조옮김 버전 등.
  각 버전의 차이를 한 줄씩 설명하고 MIDI를 모두 만든다. 고른 버전만 `app/scores/` 에 남기고
  나머지는 `scores/drafts/` 로 옮긴 뒤 `index` 를 다시 실행한다.
- 기존 곡을 고쳐 달라고 하면(예: "8마디 왼손 더 쉽게", "한 음 낮게") 해당 파일을 수정하고
  validate → index → midi 를 다시 실행한다.

## 6. 보고 (짧게)
- 만든 파일과 각 버전의 마디 수, 템포, 조
- 들어볼 MIDI 파일 경로
- 쉬움/보통에서 바꾼 점 요약(3~5줄)
- 확신이 없어 "확인 필요"인 마디 번호
- 안내: "앱에서 🎧 미리 듣기로 들어보고 이상한 마디 번호를 알려주시면 고칠게요."
- 앱 배포 방식이 GitHub Pages 라면 `app/` 을 다시 올려야 태블릿에 반영된다고 알린다(README 참고).
